# 対戦型間違い探し Web アプリ 要件定義書

## 1. 文書情報

- 文書種別: プロダクト要件定義書
- ステータス: 初版・基本構成決定
- 対象リリース: 最初の公開版（MVP）
- 最終更新日: 2026-09-05

本書は、対戦型間違い探し Web アプリの目的、対象範囲、基本的なゲームルール、および現時点の未決事項を定義する。

詳細な画面仕様、通信切断時の挙動、技術構成などは `docs/architecture/` の設計書で定義する。

## 2. プロダクト概要

運営が用意したイラストを使い、1人または招待された最大10人のユーザーがブラウザ上で遊べる対戦型間違い探しゲームを提供する。複数人ではリアルタイム対戦、1人では問題作成と結果確認を行う。

全参加者が同じ元イラストに対して同時に間違いを描き加える。作成完了後、全員の描画を1枚の変更後画像へ重ね、元画像と比較しながら間違いを早押しで発見する。

規定のラウンド終了後、ゲーム全体の結果と順位を表示する。

## 3. サービスの目的

- 一般ユーザーが、友人同士で気軽にリアルタイム対戦を楽しめること
- 問題を解くだけでなく、参加者自身がその場で問題を作れること
- インストールやアカウント登録を必須とせず、ブラウザから参加できること

## 4. 想定ユーザー

- 一般ユーザー
- 招待 URL またはルームコードを共有できる友人同士のグループ
- スマートフォンを主に使用するユーザー
- PC ブラウザから参加するユーザー

## 5. ビジネス要件

- MVP では課金機能を設けない
- 将来的な広告収益化の可能性を考慮する
- 初期提供時は日本語を基本とする
- 日本語・英語・中国語（簡体字／繁体字）・韓国語・ドイツ語・フランス語・スペイン語・ポルトガル語（ブラジル）に対応し、進行中も描画や接続を失わず即時切替できる

## 6. MVP の目標

ユーザーが部屋を作成し、1〜10人でゲームを開始してから、全ラウンドを終えて最終結果を確認するまでの一連の体験を提供する。

MVP の成立条件は以下とする。

1. ホストが対戦部屋を作成できる
2. ホストが他のユーザーを部屋へ招待できる
3. 1〜10人のユーザーがニックネームを使って参加できる
4. ホストがゲームを開始できる
5. 各参加者が問題を作成できる
6. 他の参加者がリアルタイムに回答できる
7. ラウンドごとの結果を確認できる
8. 全ラウンド終了後に最終結果と順位を確認できる

## 7. 対応環境

- ブラウザで動作する Web アプリとする
- スマートフォンでの利用を優先する
- PC ブラウザでもプレイ可能とする
- オンライン接続を必須とする
- MVP では PWA、オフラインプレイ、ネイティブアプリを対象外とする

## 8. ユーザーと認証

### 8.1 MVP の方針

- アカウント登録およびログインを必須としない
- ユーザーは対戦部屋への参加時にニックネームを設定する
- 部屋を作成したユーザーをホストとする

### 8.2 ホスト権限

ホストのみが以下の操作を行える。

- ゲームの開始
- ゲームの強制終了

ホストが切断して一定時間復帰しない場合、接続中の参加者で参加順が最も早い人へホストを移譲する。

## 9. 対戦部屋

### 9.1 参加方式

- ホストが対戦部屋を作成する
- 招待 URL またはルームコードを用いて友人を招待する
- 不特定ユーザーとのランダムマッチングは MVP の対象外とする

### 9.2 参加人数

- 最小参加人数: 1人
- 最大参加人数: 10人
- ゲーム開始後の途中参加は認めない

### 9.3 部屋の保持期間

- 未開始の部屋で全員が退出した場合、30分後に削除する
- 進行中の部屋で全員が切断した場合、2時間後に削除する
- 最終結果を表示した部屋は2時間後に削除する
- 同じ部屋で再試合を開始した場合、削除予定を更新する

## 10. ゲーム進行

### 10.1 基本構造

- 待機画面上部に「遊び方」ボタンを置き、「描く・探す・競う」の3ステップと、配点・誤答ペナルティをモーダル表示する。面積別得点は意味を先に説明し、「大きさ／見つけた人／描いた人」の表で示す。自動保存の説明と配点の常設表示はしない（設定の即時保存は維持）
- 「退出する」は即時退出せず、アプリ内の確認ダイアログで確認後にルームから退出する
- 待機画面は参加者とゲーム設定を並べ、下部に「招待URLをコピー」「QRコード」「ゲーム開始」を配置する。ルームコードは招待URLコピーの下へ常設する。参加者には設定値を操作不可のラベルで表示する
- 待機画面の設定欄は「イラスト｜ゲーム設定」のタブで切り替え、どちらも画面サイズに対して同じパネル高・横幅を保つ。画面高が変わっても下部操作を常に表示し、中央パネルだけを縮める。招待URLコピーボタンは文字とアイコンに必要な幅だけで表示する
- 高さの低いデスクトップ画面ではヘッダーと余白、イラストカードを圧縮し、招待・QR・ゲーム開始の操作行をビューポート内へ常に残す
- トップページは「みんなで間違い探しを作ろう！」を主メッセージとし、元の絵と描き足し後の絵をラベルなしで縦に並べた遊び方のサンプルを表示する
- 描画フェーズの見出しには、設定された1人あたりの間違い数を表示する
- X投稿画面へ渡す本文は「まちがいパーティーで間違い探しをつくった！ #DifferenceParty」とサイトのホームURLとする。ルームコードや招待URLは含めない（他言語では同趣旨に翻訳）

- 全参加者が同じ元画像へ同時に描画する
- 各参加者は1ラウンドにつきホスト設定の1〜5個の間違いを作成する（初期値1）
- 作成フェーズ終了後、全参加者が回答者となる
- 全参加者の描画を重ねた1枚の変更後画像を回答に使用する
- ラウンド数は参加人数とは独立し、ホストがロビーで1〜10に設定する（初期値1）

### 10.2 ラウンドの流れ

1. 全参加者へ同じ元イラストを表示する
2. 全参加者が同時に設定数の間違いを描き加える
3. 複数設定時は番号で編集対象を切り替え、すべての番号が有効なときに「確定」で描画完了を通知する。確定後もフェーズ終了までは編集できる
4. 全員の描画完了または時間終了後、「間違いを統合中」画面で各端末が最新の有効な描画を1回だけ送る。準備完了後、3秒カウントダウンを挟んで回答フェーズを開始する
5. 全参加者が間違い箇所をタップまたはクリックする
6. 全発見、時間終了、またはホストの確認付き早期終了でラウンド結果へ進む
7. 時間終了後は操作なしで結果画面へ自動遷移する
8. 正解位置と得点を全員へ表示する
9. ホストの操作で次のラウンドへ進み、規定ラウンド終了後は最終結果へ進む

1人でゲーム開始を押した場合は確認ダイアログを表示する。承認後、描画の登録後に統合・カウントダウン・回答を省略し、未発見の作成者得点を計上してラウンド結果へ進む。

## 11. 問題コンテンツ

### 11.1 元画像

- 元画像は運営が事前に用意する
- 使用する画像はイラストを基本とする
- 画像生成 AI をアプリ内から直接呼び出さない
- AI で画像を生成する場合も、事前に生成・確認した画像をアプリへ登録する

### 11.2 カテゴリと難易度

- イラストはシリーズ単位で管理し、画面では「イラスト」と表示。初期設定は左上の「ランダム」とし、全シリーズを対象にする。「どうぶつ」5枚と、輪郭線のはっきりした人間中心の「まちの人々」5枚も個別に選択できる
- 将来の利用者画像対応を確認する画面モックとして「オリジナル」を表示し、カード自体を押してホスト端末内のPNG・JPEG・WebPを選択できるようにする。選択後は同じカードで画像変更でき、プレビューと削除にも対応する。独立した画像選択ボタンは表示しない。この段階ではサーバー送信、他端末同期、ゲーム利用を行わない
- オリジナル画像のゲーム利用は未実装とする。将来実装時は1部屋につき1枚・最大5MBとし、端末側で縮小・再エンコード・メタデータ除去を行って一時保存する。最終結果表示中は保持し、全員退出または部屋の有効期限到来時に部屋データとともに削除する
- オリジナル画像では元画像との色情報を使う可視面積判定と面積別配点を行わない。空描画、個数、同一参加者内の重複、回答の当たり判定は通常どおり行い、発見者／未発見作成者は固定100点、誤答は20点減点とする。この仕様もサーバー対応までは未実装とする
- 将来のジャンル追加を確認できるよう、イラスト一覧に準備中のダミージャンルを8件表示する。ロビー全体は固定したまま、イラストカード領域だけ縦スクロールを許可する
- 難易度分けの要否は未決定とする
- ロビーでシリーズのサムネイルを表示し、ラウンド開始時に選択シリーズ内からランダム選択する。複数画像のシリーズでは直前と同じ絵を選ばない

## 12. 問題作成

### 12.1 基本操作

- 全参加者は、同じ元イラストの上から同時にペンで自由に描き加える
- 元イラストの内容を消去、移動、変形する編集は行えない
- スマートフォンでは2本指のピンチ操作、PCではマウスホイールで描画キャンバスを拡大・縮小できるようにする
- 「確定」は参加者の描画完了通知であり、描画データの登録操作ではない。描画データは描画フェーズ終了時に一括登録する
- 複数設定時は番号ごとに描画を保持し、選択番号だけの編集表示と「すべて表示」を切り替える
- 正解領域の具体的な生成・調整方法は詳細設計で定義する

### 12.2 間違い数

- 間違い数は1人あたり1〜5個、初期値1。1つの間違いには複数の線を含められる
- 将来的なルール変更を考慮し、固定値を前提としない
- 問題作成者が制限時間内に規定数を作成できなかった場合、1個以上作成済みであれば、その数で回答フェーズを開始する
- 描画中の線は同期せず、終了時に最新の番号別描画を1回だけ送信する。空・小さすぎる描画と、同じ参加者内で先行番号に重複する後続番号は除外する
- 複数設定時は全番号が有効になるまで確定ボタンを無効にし、未完成・小さすぎる・重複した番号を赤く表示する。1個設定時は個数不足・重複判定を表示せず、小さすぎる判定だけを行う
- 間違いを1個も作成できなかった場合、そのラウンドをスキップする

### 12.3 作成中の情報制御

- 問題作成中の画像および描画内容は回答者へ公開しない
- 各参加者には自分の端末内の描画だけを表示する。他人の描画はカウントダウン終了まで非公開

## 13. 回答

### 13.1 基本操作

- 回答者には元画像と全参加者の描画を重ねた変更後画像を提示する
- 回答画面では、元画像と変更後画像を端末の表示領域内で可能な限り大きく表示する
- 描画中・回答中は通常ヘッダー、言語選択、画面見出しを表示せず、時間・操作・ホストの早期終了を上部固定ツールバーへ集約して画像を最大表示する
- 回答中はPC・横画面で2枚を左右表示し、スマートフォン縦画面では元画像と変更後画像を切り替えて1枚ずつ最大表示する
- 元画像と変更後画像は同期して拡大・縮小・移動できるようにする
- スマートフォンでは2本指のピンチ操作、PCではマウスホイールで回答画像を拡大・縮小できるようにする
- 画像の並べ方は画面幅に応じて調整し、スマートフォンでの視認性を優先する
- 回答者は間違いと判断した箇所をタップまたはクリックする
- 回答受付は「もとの絵」と「間違いのある絵」の両方で行い、どちらを押しても同じ正解座標として判定する
- 回答結果は押した位置に「正解！+得点」または「不正解 -20点」の形式で一時表示する。不正解は他の参加者へ画面表示せず、回答者本人の不正解表示の直下にクールタイムの残り秒数を表示する

### 13.2 早押し判定

- 各間違いについて、最初に正解した回答者のみが得点する
- 複数人が同じ間違いを繰り返し獲得することはできない
- 自分が作成した間違いには回答できない（正誤判定・加減点なしで案内する）
- 発見後3秒で回答画面のマークと該当描画を消す。結果画面の保存描画は消さない
- 最後の正解後も3秒間は回答画面で位置を確認してから結果へ自動遷移する
- 正解が発生した場合、正解位置と正解したユーザーの名前を全参加者へリアルタイムに表示する
- 誤回答の位置は他の回答者へ表示しない

## 14. 得点と勝敗

- 可視変更面積に応じて発見者／未発見の作成者へ配点する。小（1%未満）150／50点、中（1%以上3%未満）100／100点、大（3%以上）50／150点
- サーバーが元画像との色差から面積を再計算する。ほぼ同色の塗りは面積に含めず、可視変化が小さすぎる描画や既確定部分だけの重ね塗りは拒否する
- 各ラウンド終了後、正解位置と参加者の得点を表示する
- 全ラウンド終了後、合計得点に基づく最終結果と順位を表示する
- 最終結果画面では、全参加者の描画を重ねた画像と、各参加者の描画だけを表示した画像を切り替えて確認できる
- 結果画面では元画像と表示中の変更後画像の右に、個別保存用のダウンロードアイコンを表示する。PCでは各画像にコピーアイコンも表示し、合成画像には「間違い探しを保存」・コピーアイコン・「Xへポスト」を並べる。X投稿画面へは本文とホームURLだけを渡し、利用者がコピー済み画像を貼り付ける。スマートフォンではコピーアイコンとX投稿を表示せず、「共有」と「間違い探しを保存」を表示する
- 誤回答は3秒間再回答不可・20点減点。合計得点の下限は0点。再送、禁止期間内、既発見箇所への回答は追加減点しない（ユーザー承認済み）
- ラウンド結果に発見・未発見ボーナス・誤答減点の内訳を表示。最終結果は最高点の全員をハイライトし、同点者は同順位とする
- 面積別得点案はユーザーの「ごめんこれ承認します」で承認済み。判定閾値・近似の制約は `docs/architecture/visible-scoring.md` を参照

## 15. 制限時間とヒント

- 問題作成フェーズに制限時間を設ける
- 回答フェーズに制限時間を設ける
- ホストはロビーで作成時間と回答時間を設定できる
- ヒント機能の要否および仕様は未決定とする

## 16. MVP の対象外

以下は MVP の必須範囲に含めない。

- ユーザーアカウント登録およびログイン
- 不特定ユーザーとのランダムマッチング
- プレイ履歴
- お気に入り
- ゲームの途中保存
- 全ユーザーを対象とするランキング
- ユーザーによる元画像の投稿
- 課金および決済
- オフラインプレイ
- PWA およびネイティブアプリ
- 不適切コンテンツの通報機能
- アプリ内での画像生成 AI の実行

## 17. 将来検討する機能

- 広告掲載
- 翻訳のネイティブ話者レビュー
- ユーザーによる問題または元画像の投稿・共有
- カテゴリおよび難易度
- 管理画面による元画像の追加・編集・公開管理
- 閲覧数、クリア率、誤タップ位置などの分析
- ヒント機能
- ルームごとのゲームルール設定
- 作成者数またはラウンド数を限定する短時間モード

## 18. 非機能要件の基本方針

詳細な数値目標は別途定義するが、以下を基本方針とする。

- 2〜10人の対戦状態をリアルタイムに同期でき、1人プレイでは回答フェーズを省略して結果まで完了できること
- スマートフォンのタッチ操作で快適に遊べること
- PC のマウス操作でも遊べること
- 早押し結果の確定は参加者の端末ではなく、サーバー側で一貫して行うこと
- 将来の多言語化を妨げないこと
- ゲームルールの数値をコード内へ分散させず、変更可能な設定として管理できること
- ブラウザページ全体と各コンテンツ領域はビューポートに固定し、通常スクロール・モーダル内スクロールを使用しない。ロビーのイラストカード一覧だけは、ジャンル増加へ対応するため領域内の縦スクロールを許可する
- 情報量が画面高を超える画面は、常設情報の削減、コンパクト表示、タブ、ページ分割、モーダルのページ切り替えによって収める
- スマートフォンの回答画面は「元の絵／変化後」を切り替えて1枚ずつ表示し、結果画面は「ランキング／作品」を切り替える

## 19. 未決事項

2026-08-30追記: 本節は初期の検討リスト。前節で決定済みの人数・間違い数・デッキ・ラウンド数・色と太さ・多言語・誤回答ペナルティは保留ではない。詳細な操作仕様は `docs/architecture/interaction-update.md` を参照。

以下は詳細要件または設計段階で決定する。

- 回答できる画像の範囲
- 問題作成時間と回答時間
- 1ラウンドあたりの標準間違い数
- 正解、未発見、誤回答の配点
- 誤回答時のペナルティ
- 同点時の順位決定方法
- ヒント機能
- ペンの色、太さ、最小描画サイズ
- 間違い同士の重複および最小距離
- 参加者減少時のゲーム継続条件
- 元画像の縦横比と必要枚数
- カテゴリおよび難易度
- 管理画面の要否
- 分析機能の要否

これらは MVP の基本構造を変更しない範囲で、画面設計、プロトタイプ、またはテストプレイを通じて決定する。

## 20. 用語

| 用語 | 定義 |
| --- | --- |
| ホスト | 対戦部屋を作成し、ゲーム開始などを操作するユーザー |
| 参加者 | 対戦部屋に参加している全ユーザー |
| 問題作成者 | 作成フェーズで元画像へ間違いを描き加える全参加者 |
| 回答者 | そのラウンドで間違いを探すユーザー |
| 元画像 | 運営が事前に用意した、変更前のイラスト |
| 変更後画像 | 全参加者の描画を元画像へ重ねた回答用画像 |
| 間違い | 問題作成者が番号別に作成し、描画フェーズ終了時に登録される描画と正解領域 |
| ラウンド | 全員による同時作成、回答、結果表示までの一連の進行（内部API名 stageNo は互換性のため維持） |
| フェーズ | ラウンド内の描画、カウントダウン、回答、結果などの状態 |
| MVP（最初の公開版） | 友達を招待し、描画、回答、最終結果まで遊べる必要最小限のバージョン |
