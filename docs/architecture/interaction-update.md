# 2026-08-30 操作・通信更新

ロビーは参加者欄と常設のゲーム設定欄を並べ、スマートフォンではタブ切替する。招待URLコピーは直接クリップボードへ書き込み、QRコードは独立ボタンから表示する。「オリジナル」画像は画面検証用のローカルObject URLだけを使い、通信コマンドには含めない。

## 2026-09-05 ロビー・共有・1人プレイの更新

- ロビーの「イラスト｜ゲーム設定」は同一の外枠を使い、切替時に縦幅・横幅を変えない。ビューポートが低い場合も下部の招待・QR・ゲーム開始を隠さず、イラストカード一覧だけを領域内スクロールさせる。
- イラストの初期値は左上の「ランダム」。ランダムは現在利用可能な全シリーズを抽選対象とし、可能な限り直前の画像を避ける。
- 「退出する」はアプリ内確認ダイアログを経て実行する。参加者が1人のときはゲーム開始前にも確認ダイアログを表示する。
- 1人プレイは描画データの登録後、統合表示・カウントダウン・回答フェーズを省略し、未発見作成者の得点を計上してラウンド結果へ進む。既存部屋の保存設定も現在の最小人数1へ補正する。
- PCの結果画面は、元画像・変更後画像ごとにコピー／保存アイコンを表示し、合成画像には「間違い探しを保存」・コピーアイコン・「Xへポスト」を表示する。Xには「まちがいパーティーで間違い探しをつくった！ #DifferenceParty」とホームURLだけを渡し、画像は利用者が貼り付ける。
- スマートフォンはコピーとX投稿を表示せず、OS共有の「共有」と「間違い探しを保存」を表示する。端末がファイル共有に対応しない場合は保存へフォールバックする。
- オリジナル画像は引き続き画面確認用であり、サーバー送信・他端末同期・ゲーム利用は未実装。将来の一時保存API案は [API設計](api.md) を参照する。

## 2026-09-01 トップ・ルール・共有文言の更新

- トップのキャッチコピーを共同制作が伝わる文言へ変更し、元画像と専用の間違い版画像をラベルなしで縦に並べてゲーム内容を視覚化する。間違い版は元画像と同じ1536×1024で用意し、実ゲームの描画レイヤーとは分離したトップ専用アセットとして配信する。ファイル名末尾を `-changed.png` とし、サーバー判定用RGB生成から除外する。
- ルールモーダルは「描く・探す・競う」の番号付き3ステップを先に示す。自己回答禁止の重複説明は置かず、面積別得点は目的の説明と3列の表に分け、誤回答は減点されることだけを簡潔に示す。
- 描画中は通常ヘッダーと見出しを外し、上部ツールバーと番号切り替え以外を画像領域へ割り当てる。
- 全画面でブラウザページと主要コンテンツ領域をビューポートへ固定し、通常スクロール・モーダル内スクロールを使用しない。ロビーのイラストカード一覧のみ、ジャンル追加へ対応する例外として領域内スクロールを許可する。トップは説明を短くし、スマートフォンの回答は画像切り替え、結果はランキング／作品タブで情報量を分割する。
- 描画の「確定」は完了通知だけを送り、全員確定または時間切れ後の`DRAWING_FINALIZING`で接続中端末が最新の有効描画を1回だけ一括送信する。サーバー準備後に既存の3秒カウントダウンへ進む。
- Web Share API とX投稿画面の本文は「まちがいパーティーで間違い探しをつくった！ #DifferenceParty」。XにはホームURLも渡し、招待情報は含めない。
- 全発見後の回答リビールは「すべて発見！」のみ表示し、従来どおり短い確認時間を維持する。
- 上記文言は既存9言語へ展開する。

## 2026-08-31 ルール・通知・縦長共有の更新

- 待機画面から保存説明と配点の常設文を削除。「ルールを見る」でnative dialogを開き、遊び方・自己回答禁止・配点・誤答ペナルティを表示。全参加者が利用可能。閉じるボタン／Escape、フォーカス制御、背景スクロール停止、375px幅に対応。
- ホスト専用終了ボタンは回答フェーズだけに表示する。描画は全員確定または時間切れで終了する。
- 描画の可視面積・個数・同一参加者内の重複は端末内で事前判定し、未完成番号を赤く表示して確定ボタンを無効にする。サーバーも一括受信時に再検証する。
- 元の絵のタップはローカル案内のみ。answer.submitを送らず、得点／発見状態／クールダウンに影響しない。案内は3秒後に消す。同期ズーム・移動・ピンチは維持。
- SNS共有PNGは1080×1920（9:16）。元画像を上、間違いのある絵を下に配置し、ラベルは絵の外へ。紺・白・黄のデザイン、実個数、選択ラウンド・参加者の描画、端末共有／保存は維持。縦横比を保ち切り抜かない。
- 新規／更新文言は既存9言語へ展開。実機SNSアプリでの投稿完了は別途確認が必要。

後続のUI・自作回答防止・得点内訳・最後の正解の待ち時間・共有デザインは [第2回更新](iteration-2.md) を優先する。承認済みの面積別得点は [可視面積判定](visible-scoring.md) を参照。

## 設定と進行

- ロビー設定は項目単位のpatchで即時保存。開始ボタンは保存ACKまで無効。サーバーがホスト権限と値を検証する。
- ラウンド1〜10（初期1）、各人の間違い1〜5（初期1）、描画／回答30〜300秒。デッキ初期値はランダムで、利用可能な全シリーズから直前と重ならないよう画像を選択する。
- DRAWING → DRAWING_FINALIZING → COUNTDOWN（3秒）→ ANSWERING → ROUND_RESULT → 次ラウンドまたはFINAL_RESULT。
- 描画は全員確定または時間切れで終了し、ホストの早期終了は回答だけで利用する。有効な描画が0件なら回答をスキップする。
- 旧保存データは既定設定とrounds空配列を補完する。旧imageUrl設定は受理するがデッキ抽選を優先。

## コマンドと状態

- sharedの判別unionで全コマンドを検証。commandIdで参加者別に重複排除、gameNo/stageNoで遅延した操作を拒否。
- DOの非同期処理は直列化し、保存・snapshot配信後にcommand.ackを返す。`drawing.ready`は描画を含めず、`drawing.submit`だけが終了時の最新描画を運ぶ。
- 描画中は参加者別の完了状態だけをsnapshotで共有し、他人の線はカウントダウン終了まで送らない。
- answer.resultは参加者ID、判定、時刻、正解のdifferenceIdのみ。誤答座標や秘密情報は配信／ログしない。
- 回答者本人の端末は送信直前の座標をローカル保持し、answer.result受信時に押した位置へ得点付きの正誤表示を重ねる。元画像側のクリックも同じanswer.submitとして送る。
- 誤答後3秒のサーバー強制クールダウンと20点減点、最低0点（ユーザー承認済み）。既発見への回答・同一コマンド再送・禁止期間内の再回答は追加減点なし。公開通知のscoreDeltaは実際の得点変化。旧保存設定もこの固定ルールへ移行し、過去の得点は変更しない。
- 各ラウンドの画像と確定線を部屋内roundsへ保存。既存の部屋有効期限を超えた永続履歴にはしない。

## 描画・回答・結果の共通UI

- 画像の自然な縦横比を維持し、ラベルを枠外に表示。canvas内ホイールとタッチ操作はページスクロールへ伝播させない。
- 正規化座標のまま100〜600%拡大。スライダー右側に全体リセット。2本指のピンチ／パン、PCホイール、移動モードを共通化。
- ツールバーは折り返し、スマホで横スクロールを要求しない。描画側にペン／移動／スポイトアイコン、色・太さのプレビュー、戻す／消去を配置。
- プリセット黒白、任意色入力とcanvasからのスポイト。最細線幅は短辺の0.001。描画中は十字を出さず実際の色・表示線幅の丸いカーソルを使い、Spaceを押している間は一時的にスポイトへ切り替える。
- 正誤フィードバックは全員に3秒表示。正解線の形に沿った強調を3秒表示し、チェックボックスで隠せる。結果では全線の強調を任意表示。
- LanguageContextに9言語を持ち、文字列だけ再描画。通信・下書き・選択中の画像は言語変更でリセットしない。

## 結果と共有

- ラウンド／最終結果のレイアウトを共通化。全部入りを初期表示し、参加者別の線・最終結果のラウンドを切替できる。
- 元画像と変更後画像を上下に並べて実際の間違い数を記載した縦長PNGをブラウザ内で生成。SNS用PNGには正解強調・ニックネームを含めない。
- スマートフォンでWeb Share APIがファイル対応なら端末共有シートを開く。共有先アプリは端末に依存し、Instagram等が必ず表示される保証はしない。非対応環境はPNG保存。
- PCではClipboard APIによる画像コピー、PNG保存、X Web Intentを分離する。X Web Intentには本文とホームURLだけを設定し、利用者がコピーした画像を手動で貼り付ける。サーバー画像アップロードやSNS自動投稿は行わない。

## 検証

`npm run typecheck`、`npm test`、`npm run smoke`（ローカルWorker必要）、`npm run build`、`npm run test:e2e`。
Playwright初回は `npx playwright install chromium firefox webkit`。WindowsはNode.js 22以上を使用。
実機SNS共有シート／実機タッチは自動ブラウザ検証とは別で、対応端末での確認が必要。
