# システム全体設計

## 1. 目的

1〜10人がログインなしで部屋へ集まり、複数人では同じイラストへ同時に描画して、重ねた間違いをリアルタイムに早押しで発見できるWebアプリを構築する。1人プレイでは回答を省略して作成結果を確認する。想定規模は同時10部屋、最大100人程度とする。現行UI・ACK通信・カウントダウン・共有の詳細は [操作・通信更新](interaction-update.md) を参照する。

## 2. 採用技術

| 領域 | 採用 | 理由 |
| --- | --- | --- |
| 画面 | React + TypeScript + Vite | 状態を型安全に管理し、静的配信しやすい |
| 描画 | HTML Canvas 2D | スマホでの自由描画と合成が軽量 |
| 通信 | WebSocket | 部屋内イベントを双方向に即時配信できる |
| API | Cloudflare Workers | 常駐サーバーを管理せず通信を受け付けられる |
| 部屋 | Cloudflare Durable Objects（SQLite） | 1部屋を1処理単位にし、早押しを直列に確定できる |
| 元画像 | リポジトリ内の静的ファイル | 初期運用が単純で費用がかからない |
| 自動化 | GitHub Actions | テスト、確認環境、本番公開を自動化できる |

## 3. 全体構成

```text
スマホ / PC
  ├─ 静的画面・元画像 ──────> Cloudflare Static Assets
  └─ HTTPS / WebSocket ─────> Cloudflare Worker
                                  └─ 部屋IDで振り分け
                                      └─ Durable Object（1部屋に1個）
                                          ├─ 参加者とホスト
                                          ├─ ゲーム進行
                                          ├─ 描画データ
                                          ├─ 正解判定と得点
                                          └─ 自動削除時刻
```

部屋に関する正しい状態は常にサーバー側が持つ。画面側は操作を先に表示してもよいが、サーバーの応答で必ず確定または取り消す。

## 4. 責務

### 画面側

- 画面表示、入力、Canvas描画、ズームと移動
- 線データの間引きとまとめ送信
- WebSocket切断の検知と再接続
- サーバー状態からの画面復元
- SNS共有用画像の端末内生成

### Worker

- 部屋作成・参加用HTTP API
- 入力形式、サイズ、送信頻度の検証
- 部屋IDに対応するDurable Objectへの転送
- 静的ファイル配信と安全用ヘッダー

### Durable Object

- 参加順、ホスト、接続状態の管理
- ゲーム状態の遷移
- 描画確定と回答受付
- 早押しの一意な確定、得点計算
- 再接続用スナップショットの保存
- 期限切れ部屋の削除

## 5. 基本方針

- ログインは使わず、端末に生成した参加者IDと部屋専用の再接続情報を使う。
- ルームコードは短く入力しやすい値、内部IDは推測困難な値として分離する。
- 座標は画像左上を原点とする0〜1の割合で保存する。
- ゲーム時間、得点、最大人数などは共通設定へ集約する。
- 表示文言は翻訳キーで管理し、将来の多言語化に備える。
- 元画像の追加は最初の公開版では再公開を必要とする。

## 6. 品質目標

- 2〜10人の部屋で進行状態が食い違わず、1人の部屋でも描画から結果まで完了できる。
- 通常時の操作結果を体感1秒以内に全員へ表示する。
- 一時切断から30秒以内に復帰した場合、同じ参加者として戻れる。
- 同じ間違いを同時に押しても、得点者は必ず1人になる。
- スマホ縦画面を主要対象とし、PCでも同じ機能を提供する。

## 7. 対象外

アカウント、ランダム対戦、永続ランキング、ユーザー投稿、管理画面、決済、オフライン対応は最初の公開版に含めない。
