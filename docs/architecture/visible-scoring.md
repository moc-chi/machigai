# 可視面積別得点（2026-08-30承認）

## 配点と権威

`packages/shared/src/scoring.ts` のAREA_RULESを唯一の数値定義とする。
小（1%未満）発見150／未発見50、中（1%以上3%未満）100／100、大（3%以上）50／150。
誤答3秒・20点減点・下限0、自己回答不可、最初の正解者のみ加点は維持。
確定時にサーバーが配点を保存。クライアント申告の面積・配点は無視する。
旧保存データでpointsがない確定済みの間違いだけ固定100点へフォールバックする。

## 可視性の近似と不正対策

- 元PNGをビルド時に幅1024px・元の縦横比でnearestサンプリングし、RGBデータを静的アセットとして生成。実行時の任意URLやユーザー画像は受け付けない。
- DOはASSETSバインディングから該当データを取得し、サイズを検証して部屋内でキャッシュする。読めない場合は確定拒否し、下書きを保持する。
- Canvasと同じ二次曲線・丸い端・短辺基準の太さをソフトウェア描画。2×2サブピクセルでアンチエイリアスを近似し、色は線の順に合成する。
- 元画像とのRGB各チャンネルの差の最大値が32以上のサンプル画素を数える。ほぼ同色の塗りは数えない。重ねた線は最終色で判定し、矩形や線の長さは使わない。
- 可視16画素未満は確定不可。同じ作成者の既確定部分は面積から除外し、同じ箇所を繰り返し配点へ使わせない。拒否時は確定数を増やさない。
- 回答の当たり判定も可視画素の領域＋従来のタップ余白を使う。不可視の長い線の端を押して正解することを防ぐ。
- 1回のラスタライズは走査候補800万画素まで。超過は専用エラーで拒否し、線を減らすよう9言語で案内する。
- 可視領域はサーバー内部に行ごとの区間で保存し、公開snapshotやラウンド履歴へ含めない。公開配点だけ各間違いのpointsに格納。

## 制約

人間の視認性を完全判定するものではない。色覚、端末、背景の複雑さ、サンプリングやブラウザのアンチエイリアス差で結果は変わる。閾値付近はプレイテストで調整が必要。
面積は各間違いを元画像へ合成した時点で確定し、他の参加者による後の重なりでは再配点しない（描画中の他人の線は秘密）。同じ作成者の重複は除外するが、異なる作成者の偶然の重なりは従来同様に残る。
汎用的な不正検出や知覚モデル、画像アップロード、外部AI判定は追加しない。

## 再現・検証

Node.js 24、`npm ci`後に`npm run build`または`npm run dev`でRGBデータを生成する。sharpは開発時だけ使用し、Workerへネイティブ依存を持ち込まない。生成RGBはGit対象外、元PNGと生成スクリプトを管理する。
単体で境界値・同色・低色差・重ね塗り・元色への塗り戻し・細線・上限・可視ヒット領域を検証。結合で偽装配点無視、不可視／重複拒否、小／大の配点、減点・重複再送・内訳整合を検証。
