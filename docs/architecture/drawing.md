# 描画・合成・正解判定設計

2026-08-30: 共通canvas、100〜600%ズーム、短辺0.001の細線、スポイト、形状強調、PNG共有は [操作・通信更新](interaction-update.md) を参照。

## 1. 描画データ

SVG文字列や完成画像ではなく、ペンの軌跡を構造化データとして保存する。表示はCanvas 2D、共有時はPNG、必要な場合のみSVGへ変換する。

```ts
type Stroke = {
  id: string;
  color: string;
  width: number;       // 元画像短辺に対する割合
  points: Array<{
    x: number;         // 0〜1
    y: number;         // 0〜1
    pressure?: number; // 0〜1
    t: number;         // 線開始からの経過ms
  }>;
};
```

## 2. 曲線表現

入力点を折れ線で結ばず、中点補間または二次ベジェ曲線で滑らかに描画する。近すぎる点は間引き、見た目とデータ量を両立する。

- タップのみは最小長の点として扱う。
- 急な角は過度に丸めない。
- 筆圧は将来太さへ反映できる設計にする。
- 端末間で一致するよう、補間処理を共有モジュールにする。

## 3. 操作

- 1本指またはマウスドラッグ: 描画
- 2本指: 中心位置を保ったピンチズーム
- PCのホイール: ポインター位置を中心にズーム
- 移動モード: 1本指またはドラッグで表示位置を移動
- 拡大率: 初期100%、範囲100〜300%
- 取り消し: 線単位
- 全消去: その参加者の未確定線だけ
- 描画座標はズームと移動を逆変換して0〜1へ正規化する

## 4. 間違いの確定

「この間違いを確定」を押した時点で、未確定の全Strokeを1つのDifferenceとして送る。最初は1人につき1ステージ1個とするが、上限は設定値として持つ。

サーバーは、線があること、点数・線数・データサイズ、座標・太さ・色、画像領域、二重確定を検証する。

## 5. 正解領域の自動生成

各線分の周囲を太らせた領域の和集合を正解領域とする。最初は複雑な多角形ではなく、線分カプセルの集合と全体の外接矩形を保存する。

```text
判定半径 = max(描画線幅 / 2 + 余白, スマホで押しやすい最小半径)
```

初期値は元画像短辺の2.5%を最小判定半径、描画線の周囲に1.0%を追加する。回答が外接矩形外なら即不正解、内側なら各線分との最短距離を調べる。値はテストプレイ後に調整する。

## 6. 重複する間違い

異なる参加者の領域が大きく重なると区別できないため、確定時に重複率を計算する。

- 初期方針: 重複を検出したら描き直しを求める。
- 初期しきい値: 外接矩形の共通部分が小さい方の50%以上。
- 時間切れで描き直せない場合: 後から確定された方を無効化する。

## 7. 回答判定

- 回答は元画像基準の正規化座標として送る。
- 元画像と変更後画像のどちらを押しても同じ座標系で判定する。
- 発見済みDifferenceは対象外とする。
- 複数領域に入った場合、中心までの距離が近い未発見Differenceを選ぶ。
- 同じcommandIdの再送は二重加点しない。
- 正解者はサーバー受信順で1人に確定する。

## 8. 合成と共有画像

回答画面では元画像へ全参加者のStrokeを参加順に重ねる。最終結果では全部入りと参加者別を切り替える。SNS共有用画像はブラウザ内CanvasでPNG生成し、サーバーへ永続保存しない。
