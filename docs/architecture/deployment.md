## 1. 環境

| 環境 | 用途 | 公開方法 |
| --- | --- | --- |
| local | 開発者とAIの実装・自動テスト | Wranglerローカル実行 |
| preview | Pull Requestごとの確認 | Cloudflareの確認用公開先 |
| production | 一般ユーザー向け | Cloudflare本番公開 |

現在のHTMLモックはGitHub Pagesに残して議論用とし、本体実装の開始後はCloudflare上の確認環境を主に使う。

## 2. リポジトリ構成案

```text
apps/
  web/                 React画面
  worker/              WorkerとDurable Object
packages/
  shared/              型、検証、設定、座標計算
  drawing/             曲線、合成、正解領域
content/
  images/              元画像
  images.json          元画像目録
docs/                  要件と設計
mock/                   議論用HTMLモック
tests/
  e2e/                  複数ブラウザ対戦テスト
.github/workflows/      自動確認と公開
```

## 3. 自動確認

Pull Requestごとに次を実行する。

1. 依存関係を固定されたロックファイルから取得
2. TypeScript型確認
3. 書式・静的検査
4. 単体テスト
5. Workerを含む結合テスト
6. Web画面の本番用ビルド
7. 主要な複数人シナリオのブラウザテスト
8. 確認環境へ公開

失敗した変更は本番へ進めない。

## 4. 本番公開

- 本番公開だけは人の承認を必須にする。
- 承認後、GitHub Actionsが同じ成果物をproductionへ公開する。
- 公開後に`/api/v1/health`、部屋作成、WebSocket接続を自動確認する。
- 失敗した場合は直前の正常版へ戻す。
- データ形式変更は後方互換を優先し、移行手順と戻し方を同じ変更に含める。

## 5. 費用管理

- Cloudflare無料枠から開始する。
- リクエスト、Durable Objectの処理時間・保存量を監視する。
- 無料枠の70%で警告、90%で強い警告を出す。
- 描画途中の全点を常時配信せず、確定時送信を基本として消費を抑える。
- 有料化が必要になった場合は、原因と月額見込みを確認してから人が承認する。

## 6. 運用確認

最低限、部屋作成成功率、WebSocket接続失敗率、再接続成功率、操作応答時間、予期しないゲーム終了、回答判定エラーを確認する。個人を追跡する分析は最初は行わない。

## 7. バックアップ

部屋は短期データのため長期バックアップ対象外とする。元画像、目録、設定、スキーマ、ソースコードはGitで履歴管理する。障害時は進行中の部屋を復元できない可能性を許容し、復元不能時の案内を用意する。

## 8. 一時公開の手順（今後のAI向け）

このプロジェクトの「公開」は、本番と明示されない限り、Wranglerの一時アカウントによる確認用公開を指す。正式アカウントへの接続、有料契約、本番公開への同意ではない。公開依頼がないときは勝手に公開しない。

1. ブランチ・作業ツリー・公開対象を確認し、利用可能な型検査・テストを実行する。未実施のチェックは報告する。
2. Node.js要件を満たす環境で `npm run build` を実行する。Workerのビルドはドライランなので公開されない。
3. `npx wrangler deploy --config apps/worker/wrangler.jsonc --temporary` で一時公開する。ログイン必須と決めつけたり、本番用GitHub Actionsを実行したりしない。
4. 有効な一時アカウントはWranglerが再利用する。期限切れ・未保存の場合は新規作成が必要。利用規約・プライバシーポリシーへの同意を伴うため、説明して明示的同意を得てから進める。無断で確認プロンプトへ yes を入力しない。
5. 実際の公開URLのトップ画面、`/api/v1/health`、静的画像、部屋作成・WebSocket接続を確認する。結合スモークは `BASE_URL` に公開URLを設定して `npm run smoke` で実行する。
6. 公開URL・期限・アカウントの再利用/新規・検証結果を報告する。期限やURLを推測しない。一時公開を本番公開と呼ばない。
